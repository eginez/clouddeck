# code-nav: read Rust by symbol, not by file

`scripts/code-nav.sh` (run from the repo root) wraps rust-analyzer. Reading a
1000-line file to look at one 30-line function costs ~30x the tokens it needs.
Use these four commands first; fall back to Read with `offset`/`limit` only for
lines they do not cover.

| Command | Answers | Speed |
|---|---|---|
| `scripts/code-nav.sh outline <file.rs>` | every item in the file with its line range and signature | instant |
| `scripts/code-nav.sh def <symbol>` | `file:line (lines a-b)` and signature of each definition | ~1 s |
| `scripts/code-nav.sh show <symbol>` | only that item's source, with line numbers (doc comments included) | ~1 s |
| `scripts/code-nav.sh refs <symbol>` | every line that mentions the bare name (text match, `file:line` plus the line) | instant |
| `scripts/code-nav.sh refs <symbol> --precise` | semantic uses only, grouped by the exact symbol | first call 30-70 s and ~5 GB (builds a SCIP index), then instant until a .rs file changes |

Plain `refs` is a word-boundary text match over tracked .rs files: it also
returns same-named locals, comments and unrelated items. Add `--precise` only
when you need the callers of one specific item and the text list is too noisy.
Do not use `--precise` casually: it builds a 5 GB index.

`<symbol>` is a bare name (`aws_files_for`) or `Type::name` (`AwsAuth::status`,
`AwsProvider::list`). For trait impls, `Type` is the implementing type. Calls to a
trait method are recorded against the trait, so for uses of a trait method run
`refs Browse::list` (the trait), not `refs AwsProvider::list`.

## Rules

1. **Never Read a whole .rs file to find something.** Run `outline` first, then
   `show` the item, or Read just its line range (`offset` = start line, `limit` =
   range length + a few lines).
2. **Know the name? `show` it.** `show AwsAuth::begin` instead of opening
   `aws_auth.rs`. If it prints many matches, qualify with `Type::`.
3. **Looking for where something is defined:** `def`, not grep.
4. **Before changing a signature or behaviour:** `refs` to see where the name
   appears. For an exact caller list of a specific item, use `refs <symbol>
   --precise`, which is semantic, but expensive the first time. Use grep only for
   text that is not a symbol (strings, settings keys, log text).
5. **Before an Edit**, the Edit tool needs the file to have been Read in this
   session, but a ranged Read is enough: Read with `offset` = the item's start line
   and `limit` = its length + ~5 (from `show`/`outline`), then Edit. Never Read the
   whole file just to edit it.
6. After editing, line numbers shift: re-run `outline`/`show` rather than trusting
   old numbers.

## Example: fix a function in a large file

```bash
scripts/code-nav.sh outline crates/clouddeck-core/src/list_view.rs   # 513 lines -> 56 lines of outline
#   30-255   impl ListView
#  184-197     fn rows  fn(&self) -> Vec<ProviderRow>
scripts/code-nav.sh show ListView::rows       # just those 14 lines
scripts/code-nav.sh def ProviderRow           # where the return type lives -> file:line (lines a-b)
scripts/code-nav.sh refs rows                 # every line mentioning rows (text match)
scripts/code-nav.sh refs ListView::rows --precise   # exact callers only (builds the index once)
# to change rows: Read list_view.rs offset=184 limit=19, then Edit
```

To add a test, `outline` the file and Read only the tail of its `mod tests`
(the outline gives the line range) to copy the local test style.

Not covered: macros' expansions, non-Rust files (use Read/grep), and items
generated by macros (outline shows the macro call, not what it defines).
